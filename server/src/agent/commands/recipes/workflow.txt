---
title: Run a workflow and check its results
keywords: workflow, run, status, logs, automation
---

A workflow script calls extension jobs with
`await runJob("<extensionId>", "<jobId>", inputs)`. Call `list_extensions` for
the installed extensions, their job ids, descriptions and inputs; never guess a
job id. If no job does what is asked, say so.

1. Start with `run_workflow` using the workflow document ID and optional
   object-valued `inputs`. Keep the returned run ID.
2. Poll `get_workflow_run` until `status` is no longer `pending` or `running`.
   Do not start duplicate runs while polling.
3. Use `get_workflow_log` for concise `status`, `error`, and `logs`.
4. On success, inspect `resultArtifact` from `get_workflow_run`. Report its
   `url` and `key` when present; the current agent tools do not expose a direct
   artifact-content reader.
5. Use `list_workflow_runs` for recent run history. Pass `documentId` to filter
   by workflow, and follow `nextCursor` with the `cursor` argument to read
   additional pages.

The agent cannot create, list or delete workflow schedules: the schedule
routes require a signed-in user and reject the agent's job token. Say so when
asked to schedule a workflow.
